## 对当前项目的结论

| 平台 | 当前项目状态 | 可执行的合规路径 | 不能做的事 |
|---|---|---|---|
| 知乎 | 已有 `tool/crawlers/zhihu.py`，默认关闭 | 账号持有人明确授权、指定问题范围、合法登录态，或用户提供平台允许的导出文件；先做 100–300 条小试 | 不自动获取 cookie，不绕过验证码/登录墙，不做无边界全站搜索 |
| 小红书 | 当前没有适配器 | 官方批准 API、平台允许的导出，或用户提供明确的公开 URL 清单；可把搜索引擎摘要作为“标题证据”单独存储 | 不用 `xhs-cli`、登录态签名或指纹模拟绕过风控，不把摘要当正文 |
| 快手 | 当前没有适配器 | 官方开放平台 API、创作者/内容所有者授权导出，或公开 URL 小样本 | 不做全站关键词抓取，不绕过动态签名、登录和验证码 |
| 微博/抖音/X | 当前没有适配器 | 官方 API 或用户提供的授权导出；按平台单独限额和来源记录 | 不把教程链接当作 API 凭证，不执行未经审核的第三方安装命令 |

## 如果要真正开始新增数据

建议先做三个独立小试，每个平台 100–300 条：知乎指定问题、小红书公开笔记、快手公开视频。每行保留 `platform`、`source_url`、`query`、`captured_at`、`visibility=public`、`adapter_version` 和 `failure_reason`；作者信息只保留不可逆哈希或直接丢弃，默认不保存头像、联系方式、个人主页、点赞/转发明细。

通过质量门槛后，再把正文接入现有聚类；标题、搜索摘要、评论和正文分开统计，避免把工具宣传的“覆盖平台数量”误当成有效样本量。
