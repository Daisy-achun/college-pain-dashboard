# 大学生吐槽数据扩展方案

当前正文痛点集有 2,369 条，来自 B 站、牛客、虎扑和少量豆瓣。最大的结构性偏差是牛客占比高，毕业求职和计算机语境被放大。因此新增数据按“来源独立、内容层级可追溯、平台被拦就停”执行。

## 已落地

- **百度贴吧**：已有 13 个吧的 3,781 条列表候选。`expand_tieba_titles.py` 过滤后得到 2,245 条标题/列表摘要证据，接入 `college_pain_dashboard.html` 的“含标题类数据”开关。它们不计入正文痛点、主题精度和 `n_final`。
- **贴吧正文**：`tool/crawlers/tieba.py` 支持公开 WAP 列表和帖子页，建议优先使用 `wap: true`。遇到 403/412/429、安全验证或空壳页立即停止该平台。
- **知乎**：`tool/crawlers/zhihu.py` 只接受用户主动提供的登录态和明确的问题 ID；不自动获取或保存 cookie，不绕过验证码。当前默认关闭。
- **豆瓣小组**：保留公开只读路径；小组发现和帖子详情遇到登录/限流时停止，当前报告只保留人工转录的 58 条。

## 下一轮优先级

1. 从 `source_expansion/tieba_title_evidence.csv` 选取高回复、痛点词命中和不同吧的分层样本，用贴吧 WAP 正文采集器补正文；按 URL 去重后再进入通用清洗和人工抽检。
2. 在用户已登录的知乎会话中，选择 6–10 个明确的大学生痛点问题，限定回答条数和抓取间隔，单独统计知乎来源，避免直接改变总体比例。
3. 继续补充豆瓣小组和小木虫等公开页，只读抓取正文；登录墙、验证码和隐性风控一律记录为“未覆盖”，不采用绕过手段。
4. 对微博、小红书、抖音等需要登录或强风控的平台，暂不自动采集。只有在用户提供平台允许使用的公开导出或明确授权的 API 数据后，才走同一字段映射。

## 每个平台必须保留的字段

`source`、原始 URL、抓取时间、原始发布时间（无法确认就留空）、正文/标题层级、回复或点赞数、采集关键词/吧名/问题标题、阻断状态。标题证据、列表摘要和正文必须用 `evidence_level` 区分，不把标题行伪装成正文样本。

## 质量门槛

- 每个新来源先做至少 30 条人工抽检，分别评估“学生身份相关性”和“吐槽/求助有效性”。
- 主题分析按来源分层报告，并给出每个平台的有效率；新增来源不直接与牛客样本合并加权。
- 所有被 403、412、429、验证码或登录墙阻断的请求都写入运行日志，停止该平台，保留已经落盘的结果。
